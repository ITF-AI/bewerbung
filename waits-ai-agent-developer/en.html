05 / Governance & data protection

Enforce security before invoking AI.

Design principles

Minimization: only necessary fields. Access: role- and tenant-scoped authorization on the backend. Validation: types, range checks, source status and deduplication before any agent invocation. Separation: untrusted source content must never override system instructions.

Oversight: verifiable human approval for sensitive or destructive actions. Traceability: versions, hashes, decision paths and provenance. Rollback: reversible, idempotent write operations.

GDPR / production readiness

Before the pilot: check records of processing and lawful basis; verify processor agreements and subprocessors; assess data location and international transfers; implement technical and organizational measures, retention/deletion rules and data-subject rights; assess whether a DPIA is required.

This static demo does not automatically satisfy those organizational obligations. In particular, it implements no real identity and access management, backend encryption, production audit signatures or demonstrable GDPR compliance.

Microsoft Copilot integration · target design

Copilot Studio could serve as the agent interface or orchestration layer. For data processing: tightly scoped actions, Azure/API connectors, server-side authorization, idempotent queued jobs, versioned outputs and independent quality gates. GitHub Copilot assists developers; it does not replace runtime governance.

None of these Microsoft integrations is implemented in this demo.

ETL → ELT / warehouse · target design

Immutable raw layer with provenance; normalized staging layer; curated layer after approval; SQL constraints, change data capture and lineage; optional dbt tests and incremental models. Agents can propose actions; deterministic transformations and human reviewers make final decisions.

Conceptual extension for SQL Server / Snowflake / dbt, not evidence of a production implementation.

07 / Evidence & limitations

What still needs testing.

Functional tests

Invalid JSON, missing IDs, duplicate keys, content fingerprints, PII flags, negative risk values and new source versions.

Integration tests

Authentication, token rotation, SQL transactions, race conditions, idempotency, unauthorized tenants and warehouse schema changes.
