02 / Reference architecture

Build boundaries before building prompts.

01 · IntakeAuthenticated user → request schema → tenant / scope checks
02 · OrchestrateVersioned workflow + tool policy + correlation ID
03 · ExecuteBounded retries, timeouts, idempotent writes
04 · VerifyTyped output validation, evidence and human gate
05 · OperateTrace, cost, latency, quality, rollback signals

Trust boundaries

Least privilege by tenant, approval required for high-impact actions, secrets server-side, untrusted tool responses treated as data, not instructions.

Failure semantics

Transient errors retry with bounded backoff. Invalid outputs never write. Ambiguous authorization fails closed. Duplicates return the original result without repeating a side effect.

Invariants and error model

400 INVALID_SCHEMA
401 UNAUTHENTICATED
403 CROSS_TENANT_DENIED
409 IDEMPOTENCY_CONFLICT
422 EVIDENCE_INSUFFICIENT
429 RATE_LIMITED
503 TOOL_UNAVAILABLE

Operational invariants:
- no cross-tenant data in context
- no write before schema & policy pass
- retry only safe/idempotent operations
- bounded timeouts and retry budget
- explicit human approval for risky actions
- trace IDs in every error response
- remove PII from model/tool logs

Production implementation direction

API + worker: Python/FastAPI or TypeScript service; Redis-backed queue for asynchronous jobs; Postgres for durable state and deduplication; versioned tool adapters with restricted credentials. LLM: structured outputs with independent validators and test sets. Observability: OpenTelemetry traces, SLO dashboards, privacy-filtered logs, error budgets and rollback conditions. These are proposed technologies, not implemented components of this static demo.

06 / Field deployment plan

Four weeks from problem statement to an evidence-backed decision.

Week 1 / Discovery

Define the problem

Process map, owners, baseline, security boundaries, tool feasibility, integration plan and measurable success criteria.

Week 2 / Build

Ship one vertical slice

Auth-scoped API, versioned workflow, durable job state, test fixtures, exception path and operator UI.

Week 3 / Pilot

Measure with users

Shadow-mode evaluation, task success, reviewer workload, p95 latency, costs and failure distribution.

Week 4 / Decision

Scale, revise or stop

Canary release with guardrails, runbooks and ownership handoff. Roll out only if quality and operational metrics clear agreed thresholds. Otherwise capture failure modes and iterate.
