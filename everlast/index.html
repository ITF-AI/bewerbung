Implementierungsprinzip

Ein echtes Routing-Programm im Browser

Die interaktive Arbeitsprobe verwendet eine reine Entscheidungsfunktion. Eine produktive Implementierung würde dieselben Regeln serverseitig durchsetzen, jede Berechtigung in der Datenbank prüfen und den LLM-Pfad über einen abgesicherten Gateway führen.

function decide(input) {
  if (input.tenant !== 'same')
    return { route: 'STOP', reason: 'TENANT_DENIED' };
  if (input.role === 'guest')
    return { route: 'STOP', reason: 'ROLE_DENIED' };
  if (input.sources !== 'approved')
    return { route: 'STOP', reason: 'EVIDENCE_MISSING' };
  if (input.case === 'sensitive')
    return { route: 'HUMAN', reason: 'RISK_REVIEW' };
  if (input.case === 'faq')
    return { route: 'RULE', reason: 'APPROVED_ANSWER' };
  return { route: 'AI_CANDIDATE', reason: 'COMPLEX_QUERY' };
}
Sicherheitsgrenze: Eine Browser-Simulation ist kein beweisbarer Backend-Zugriffsschutz. Ein echter produktiver Dienst müsste Tenant-Isolation, RLS/ACL, Token-Prüfung, Logging, Secrets, Datenschutz und Tests serverseitig erzwingen.
